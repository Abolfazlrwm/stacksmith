# ADR-0031: v1.0.0 — stability declaration

- **Status:** accepted
- **Date:** 2026-12-15
- **Supersedes**: all previous "v0.x" stability caveats

## Context

stacksmith has shipped 9 releases (v0.1.0 through v0.9.0) over 14 phases.
Each release added a capability and proved it in CI. The kit now covers:

- Deploy (blue-green + canary + auto-rollback + deploy-time cosign verify)
- Monitor (Prometheus + Grafana + Loki + Tempo + Alertmanager + recording rules)
- Backup (encrypted + integrity-verified + freshness metric)
- Restore (one-command + DR drill for total VPS loss)
- TLS (automated certbot)
- Tracing (OpenTelemetry + Tempo)
- Secrets (automated rotation + zero downtime)
- Security (CodeQL + Trivy + dependency review + SBOM + cosign)
- Performance (k6 load test with thresholds)
- Infrastructure (multi-provider Terraform)
- Chaos (kill worker + stop nginx → verify recovery)
- Operations (maintenance mode + health CLI + capacity planning + audit log)

30 ADRs. 23 CI workflows. 18 operational scripts. 5 Grafana dashboards.
4 runbooks. OpenAPI spec. Architecture documentation with 5 diagrams.

The question: is this v1.0.0?

## Decision

Ship v1.0.0. This release declares:

1. **The operational surface is stable.** The scripts (`deploy.sh`,
   `rollback.sh`, `backup-db.sh`, `restore-db.sh`, `rotate-secrets.sh`,
   `maintenance.sh`, `stacksmith-health.sh`) have stable interfaces. A
   v1.x release will not break a script's CLI without a deprecation cycle.

2. **The CI contract is stable.** The 23 workflows are the contract.
   A v1.x release will not remove a workflow without a replacement.

3. **The ADR set is the architectural record.** 30 ADRs document every
   decision. A v1.x release will not reverse an ADR without a superseding
   ADR that explains why.

4. **The compose file is stable.** `docker-compose.prod.yml` service
   names, volumes, and healthchecks are the deployment contract. A v1.x
   release will not rename a service without a migration path.

## What v1.0.0 does NOT declare

- **The docubot application is stable.** stacksmith deploys docubot;
  docubot's stability is its own concern.
- **Multi-host HA is supported.** ADR-0015 documents what it would take;
  it is not shipped.
- **Business-endpoint load tests.** Only `/health/live/` is load-tested.
- **cosign verify at deploy time works on all providers.** It works when
  cosign is installed and the image is from GHCR; it is skipped otherwise.

## Rationale

- **v1.0.0 is a commitment, not a feature.** The kit has been feature-
  complete since v0.9.0. v1.0.0 declares that the surface is stable and
  the operator can build on it without expecting breaking changes in
  v1.x patches.

- **30 ADRs are the proof.** A v1.0.0 without written decisions is a
  version number. 30 ADRs with considered-alternatives and consequences
  are the evidence that the decisions are deliberate, not accidental.

- **23 CI workflows are the contract.** Every claim in the README is
  proven by a workflow. v1.0.0 means the contract is stable: the
  workflows will continue to run and prove what the README claims.

## Consequences

- v1.0.0 is the first stable release.
- v1.x patches add features or fix bugs without breaking the operational
  surface.
- v2.0.0 (if needed) would break the surface (rename a service, change a
  script CLI, remove a workflow) and would require a migration guide.
- The README gains a "Stability" section and a "Maturity model" table.
- The CHANGELOG for v1.0.0 includes a full capability summary.
